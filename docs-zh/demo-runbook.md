# Design Requirement Checker — 演示手册

[English source](../docs/demo-runbook.md)

本文件为同名英文文档的对应中文版本；字段、状态、路径与命令保留原技术标识。

v0.1 内部演示的简明实操指南。

## 1. 启动应用

打包的 Windows 产物：

1. 解压**整个** `DesignRequirementChecker/` 目录（单独复制 `.exe` 无法运行
   —— 相邻的运行时文件是应用的一部分）。
2. 启动 `DesignRequirementChecker.exe`。

演示用户无需安装 Python。

源码运行（开发机）：`python -m design_requirement_checker`。

## 2. 配置检查清单

点击 **检查项管理** → **新增检查项**，填写：

- `功能名称`（name）— 必填
- `编号`（code）— 必填，必须唯一
- `检测短语`（detection phrase）— 必填
- 可选：`期望描述`、`类别`、`备注`、`别名`（每行一个）

注意：**功能名称 ≠ 检测短语**。名称是给人看的标签；检测短语才是匹配器在
文档中实际搜索的内容。核查绝不只按名称匹配。

用 **编辑**、**切换启用/禁用**、**删除**（需确认）维护条目；ID 在编辑和
重启后保持稳定。点击 **保存基准** 持久化。重复编号会被拒绝；重复名称与
重叠检测短语会提示确认。

## 3. 导入 DOCX

点击 **导入 DOCX**，通过文件对话框选择 `.docx` 文件。

当前生产路径仅支持文件选择——未实现拖放导入（属延期的可用性增强）。导入
在后台执行；若文档包含已检查范围之外的结构，会显示 LIMITED 覆盖提示。

## 4. 运行核查

点击 **开始核查**。**取消核查** 请求协作式取消；被取消的运行不显示任何
结果集（取消 ≠ 完成）。

结果状态：

- **已配置**（CONFIGURED）— 找到合格且有效的证据
- **未配置**（MISSING）— *在已检查范围内* 未找到匹配证据（不证明物理上
  不存在）
- **已划除**（STRUCK_OUT）— 全部合格证据均被完整划线删除
- **待人工核查**（UNRESOLVED）— 部分／未知删除线、冲突或歧义证据；需要
  人工判断

**描述有差异** 是正交维度：一个条目可以同时是已配置*且*描述有差异。描述
差异绝不会把已配置条目变成未配置。

## 5. 审查证据

- 用 全部 / 已配置 / 未配置 / 已划除 / 待人工核查 / 仅异常 筛选，或按
  编号／名称／类别／期望描述搜索。筛选绝不重新计算核查。
- 详情面板显示期望描述与实际需求、匹配方式、原因、**每一次证据出现**
  （选择器）以及重建的源上下文（前/当前/后块，高亮要求范围）。
- LIMITED 覆盖的运行会显示持久的"检查范围受限"提示。

## 6. 持久化

检查清单基准自动保存为一个本地 JSON 文件：`QStandardPaths.AppDataLocation /
baseline.json`（另有用于恢复的 `baseline.json.bak` 备份）。应用不显示解析
后的绝对路径；在 Windows 上该位置位于每用户的应用数据目录下，而不是可执行
文件旁边。

请区分这两个概念：

- **应用目录**（解压出的 `DesignRequirementChecker/` 文件夹）随时可被新
  构建替换；
- **用户基准目录**（AppDataLocation）保存你的检查清单，在应用替换后保留。

启动时，备份恢复、损坏与不兼容 schema 的基准会以彼此明确的独立横幅提示。

## 7. 演示限制

正式历史实测（任务 6）、干净电脑／免提权／完全离线部署验证（任务 7 / S3）、
DPI／中文输入／长描述验证矩阵与报告导出在本里程碑中**延期**。见
[demo-readiness.md](../docs-zh/demo-readiness.md)。
